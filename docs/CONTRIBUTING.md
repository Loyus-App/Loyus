# Contributing to Loyus

Thanks for considering a contribution. This document covers the development workflow, CI/CD pipeline, and repository conventions.

## Dev setup

```bash
corepack enable      # once per machine — picks the Yarn version pinned in package.json
yarn install         # triggers `postinstall` script, which wires Husky hooks
```

After install, commits will run `yarn lint-staged` automatically (oxlint and oxfmt on staged files only). To skip in an emergency: `git commit --no-verify`. CI enforces the same checks, so skipping only delays the pain.

## Quality gates (local)

```bash
yarn check:fix       # oxlint + oxfmt (autofix)
yarn typecheck       # TypeScript strict
yarn test            # Jest unit tests
yarn test:e2e        # Maestro E2E (requires iOS simulator + Maestro CLI)
```

## CI pipeline

Workflows:

| Workflow            | Trigger                    | Purpose                                       |
|---------------------|----------------------------|-----------------------------------------------|
| `ci.yml`            | PR + push `main`           | Lint (OXC) / Typecheck (tsc) / Unit tests (Jest) in parallel |
| `e2e.yml`           | PR + push `main`           | Maestro E2E on macOS + iOS simulator          |
| `pr-title.yml`      | PR open/edit/sync          | Enforce conventional commit title             |
| `eas-build.yml`     | Manual dispatch            | EAS build of any profile (non-blocking, --no-wait) |
| `eas-submit.yml`    | Push tag `v*` + manual     | CI checks, production build, submit to TestFlight / Play internal |

Linux jobs run on the self-hosted ARC runner scale set `loyus-arc`; pull requests from forks run on `ubuntu-latest` instead, so outside code never reaches the cluster. E2E runs on `xcode-27`. Jobs install Node, Yarn and the dependencies through `.github/actions/install`.

### PR title convention

All PR titles must follow [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <Subject starting with capital letter>
```

Allowed types: `feat`, `fix`, `test`, `docs`, `refactor`, `chore`, `perf`, `ci`, `build`, `style`, `revert`. Scope is optional (domain layer: `domain`, state: `state`, a phase number like `06`, etc.).

### Release flow

1. Bump `version` in `app.config.ts` (and `package.json`) on `main`. Build numbers are auto-incremented by EAS.
2. Tag and push. The tag must equal `v` + that version, or the workflow stops:
   ```bash
   git tag v0.2.0
   git push origin v0.2.0
   ```
3. `eas-submit.yml` runs the CI checks, builds production on EAS, then submits:
   - iOS to App Store Connect (TestFlight). Submit for App Store review in App Store Connect.
   - Android to the Play internal track as a draft. Promote in Play Console.
4. On a tag, it then creates the GitHub release with generated notes.

Manual run with the GitHub CLI:

```bash
gh workflow run eas-submit.yml -f platform=ios                    # build + submit iOS
gh workflow run eas-submit.yml -f platform=all -f skip_build=true # resubmit latest production builds
gh run watch                                                      # follow it
```

## Release credentials (publisher-only)

Only one GitHub secret, in **Settings → Secrets and variables → Actions**:

| Secret       | How to get it |
|--------------|---------------|
| `EXPO_TOKEN` | Token of the `loyus-github-actions` robot (Developer role): https://expo.dev/accounts/<owner>/settings/access-tokens |

Store credentials live on EAS (`eas credentials`), not in GitHub:

| Credential | Platform | Setup |
|------------|----------|-------|
| Distribution certificate + provisioning profiles (`com.loyus.app`, `com.loyus.app.widget`) | iOS | `eas credentials:configure-build -p ios -e production`. Expire yearly and CI cannot renew them: run it locally with an App Store Connect API key (`EXPO_ASC_API_KEY_PATH`, `EXPO_ASC_KEY_ID`, `EXPO_ASC_ISSUER_ID`, `EXPO_APPLE_TEAM_ID`) |
| App Store Connect API key | iOS | `eas credentials -p ios` → App Store Connect API Key |
| Upload keystore | Android | Generated by EAS on the first build |
| Google service account key | Android | Service account in the Google Cloud project, invited in Play Console → Users and permissions with release rights on the app, then `eas credentials -p android` → Google Service Account |

The App Store Connect app ID and the Play track live in the `submit.production` profile of `eas.json`.

Keep `releaseStatus: draft` until the Play app is published once: Play rejects any other status on a draft app.

### Required GitHub Actions environment

The `eas-submit` workflow runs in the `production` environment, which only accepts `main` and tags `v*`. Add required reviewers there to gate each release.

## Branch protection (recommended settings)

Under **Settings → Branches → Branch protection rules** for `main`:

- Require a pull request before merging
- Require approvals — 1 (solo) or 2 (team)
- Dismiss stale reviews on new commits
- **Require status checks to pass before merging:**
  - `Lint (OXC)`
  - `Typecheck`
  - `Unit tests (Jest)`
  - `e2e-ios`
  - `PR Title / Validate conventional commit title`
- Require branches to be up to date before merging
- Require linear history (no merge commits)
- Include administrators (keeps Arthur honest too)
- Restrict who can push to matching branches — only `main` requires PR, other branches are free

## Code conventions

- Strict 4-layer architecture — see root `CLAUDE.md` and `.claude/rules/*`
- TypeScript strict, no `any` (oxlint enforces)
- No `console.log` in committed code
- New user-facing strings → add to all 6 locale files (`src/shared/i18n/locales/`)
- Domain layer → zero RN/Expo imports (test enforces)
- No network calls on critical path (test enforces)
- Commits in English; conventional style (`type(scope): message`)

## Store listing

Store texts and visuals live in the repo: `store.config.json` (App Store, through `eas metadata`) and `store/play/<locale>/` (Play).

1. Capture raw screenshots on an iPhone 17 Pro Max simulator running an `EXPO_PUBLIC_E2E=true` Release build, once per locale, with the simulator language set to that locale:
   ```bash
   maestro test .maestro/store/screenshots.yaml -e LOCALE=fr-FR -e OPEN_LABEL=Ouvrir -e CANCEL_LABEL=Annuler \
     -e SAVE_LABEL=Enregistrer -e "CLOSE_CARD_LABEL=Fermer la carte" -e SEARCH_LABEL=Rechercher \
     -e "SEARCH_PLACEHOLDER=Magasin, titulaire ou numéro" -e "SETTINGS_LABEL=Réglages" -e CARDS_LABEL=Cartes -e DARK_LABEL=Sombre
   ```
   English labels: `Open`, `Cancel`, `Save`, `Close card`, `Search`, `Store, owner or number`, `Settings`, `Cards`, `Dark`.
2. `yarn store:assets` frames them with the captions of `store/screenshots.json` (needs Google Chrome and ImageMagick).
3. Push the App Store listing: `npx eas-cli metadata:push --profile production`. The age rating is set by hand in App Store Connect: `eas metadata` does not send Apple's newer questions yet.
4. Push the Play listing: `GOOGLE_SERVICE_ACCOUNT_KEY=<key.json> yarn store:play`, with a key of the Play service account. Delete the key afterwards.
